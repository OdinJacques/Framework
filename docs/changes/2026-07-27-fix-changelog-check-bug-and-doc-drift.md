# Fix a critical changelog-check bug and several doc-drift inaccuracies

**Date:** 2026-07-27

## Summary

A morning audit (three fresh, independent reviews: README-vs-code drift, a re-check of previously-applied reliability fixes, and edge cases in the newest `changelog-check` CI job) found that all six previously-applied reliability fixes were still intact, but surfaced one critical bug and several real doc inaccuracies accumulated across the day's incremental edits. Fixed all of them.

## Files changed

- `.github/workflows/ci.yml` — **critical fix**: `actions/checkout@v4` on a `pull_request` event defaults to checking out GitHub's synthetic test-merge commit, not the contributor's real last commit, so `[skip-changelog]`'s `git log -1 --format=%B` check was reading an auto-generated merge message and could never match the marker. Added `ref: ${{ github.event.pull_request.head.sha }}` to the checkout step. Also added explicit error handling around `git fetch origin` (previously a transient network failure looked identical to "missing changelog entry" in the PR checks UI) and anchored the trivial-file allowlist regex (`^(package-lock\.json|\.gitignore|\.prettierignore)$|^docs/changes/`) so files like `package-lock.json.bak` are no longer silently treated as trivial.
- `docs/ARCHITECTURE.md` — corrected a false claim that `apps/sql` mirrors `packages/test-data` "by hand ... rather than importing it directly." It actually imports `demoUser`/`sampleProducts` directly (`apps/sql/db/seed.ts:2`). Fixed the Mermaid diagram edge and the surrounding prose in both the "Suite relationships" and `"same page" design` sections.
- `README.md` — corrected the `packages/test-data` table entry and Overview prose (now includes sql), the `APPIUM_HOST`/`APPIUM_PORT` claim (the zod schema does include them; `apps/mobile` just never consumes `@framework/config`'s `env` object at all), the CI/CD section's wording (jobs run fully independently, not "lint then web/api/sql"; artifacts upload every run via `if: always()`, not on failure only), and added a Troubleshooting bullet generalizing the "live site can change" risk beyond catalog data to exact-string UI/API copy (`login.page.ts`'s error text, `auth.service.ts`'s "not found" check).
- `CLAUDE.md` — matching fixes to the repo map (`test-data` scope, SQL's description) and the mobile/`packages/config` gotcha bullet, for the same precision reason as the README fix above.
- `apps/web/playwright.config.ts` — added `expect: { timeout: 10_000 }`. The config already documents page loads observed taking ~20s (hence `navigationTimeout: 25_000`), but `expect()`/`expect.poll()` assertions were still bound by Playwright's 5000ms default — a real path to the exact intermittent failure the navigation-timeout comment was written to prevent (e.g. `login.spec.ts`'s post-submit `expect.poll` check).
- `packages/test-data/src/sample-products.ts` — fixed its own comment's "SQL suite (seed data shaped after the same catalog)" wording to say the SQL suite seeds directly from these values, and broadened the documented live-site-drift risk to cover UI/API copy generally.
- `docs/changes/README.md` — added a "CI enforcement" section documenting that `[skip-changelog]` only reads the PR's most recent commit, not any earlier commit in the branch.

## Rationale

The `changelog-check` bug was caught by actually reproducing GitHub's synthetic-merge-commit checkout behavior in a disposable scratch repo (not just inspecting the YAML) — created a real PR-head commit containing the marker, then a *separate* synthetic merge commit exactly as `actions/checkout@v4` would produce it (critically, without touching the local `main`, mirroring how `origin/main` is never touched by a PR), and confirmed the old code failed to detect the marker while the `ref:`-pinned fix succeeded. This is the same "verify by executing, not just reading" discipline used when the job was first built — that first round tested the shell logic in isolation but never simulated the actual GitHub Actions checkout semantics for `pull_request` events, which is exactly where the bug lived.

The doc-drift items all stem from the same pattern: a fact was true when first written, then a later, unrelated change (SQL suite gaining a `packages/test-data` import, `packages/config`'s schema gaining `APPIUM_HOST`/`APPIUM_PORT` for completeness, `navigationTimeout` being raised) made the earlier documentation subtly wrong without anyone revisiting it. None of these were caught by the original fresh-agent verification passes because each pass checked internal consistency across `README.md`/`CLAUDE.md`/`docs/ARCHITECTURE.md` at a point in time — none re-verified against the actual source after subsequent code changes landed. Worth remembering: cross-doc consistency checks go stale the moment the underlying code changes again.
